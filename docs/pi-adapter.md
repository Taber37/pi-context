# Pi adapter (Pi 1.6.1)

`/gentle:context` opens the latest observation and Pi’s current projected occupancy. Use `/gentle:context all` for the origin breakdown, measurement method, and matched provider input. Both work before the first request. Use arrow keys to scroll and Enter or Escape to close. RPC clients receive a UI notification; print and JSON modes have no report UI. Unknown values are not zero. The command does not call a model, append history, change MCP configuration, or compact a session.

The adapter measures the full logical transcript at `context_with_system`, not the session file. When the selected model uses flat, streaming `openai-completions`, a recognized `before_provider_request` body replaces that view with a separate fragment snapshot; the two views are never added. Chat fragments count prompt text and tool declarations/calls/results, treat media/opaque blocks as unknown tokens, and omit protocol framing, controls, and headers. Logical transcripts can contain older patches that providers fold away and visible thinking that not every provider replays. Later extensions can rewrite either observation. Neither view is a wire capture or an exact model tokenizer.

Codex and other OpenAI Responses variants (including Azure), Anthropic, Bedrock, Gemini/Vertex, and other APIs or custom transports use the logical-transcript view only. In particular, it is not a byte count of a Codex or Anthropic continuation. Mid-conversation Chat Completions tool patches and unrecognized Chat Completions payloads also fall back. Provider usage is shown only for a matched Chat Completions turn with one request hook, one successful HTTP response, matching stream and assistant model, and positive `usage.prompt_tokens` agreeing with the final normalized input plus cache read and write. Missing, ambiguous, and synthetic placeholder usage stays unknown. No public hook certifies that a later hook left the body unchanged, so discrepancy is always unknown.

MCP attribution uses Pi’s built-in `ToolInfo` source and namespace metadata and exact observed tool declarations. The logical-transcript view can also attribute lines in Pi’s structured `mcp_servers` section. In Chat Completions, that section is folded into system or developer text with no separate provenance. The adapter counts all of that text as system input, derives exposure from registry metadata alone, and reports announcement savings and combined savings as unknown, even if the logical view had a structured section. Zero attributed announcement bytes in this view does not mean no announcements were sent. Eligible declaration savings remain available in `all`. Shared discovery and resource tools are never charged to one server. Missing registry evidence, omitted/ambiguous announcements, and unexpected changes can leave savings unknown. A server without matching metadata (for example one that has not connected yet) may not have a row. A retained-history cell is an attributed subtotal, not proof that the server has no history; the current registry does not identify the owner of a prior call. Retained results are still counted in the aggregate. Savings are conditional on the observed loadout and exclude shared overhead and retained history. See [the synthetic on/off experiment](baseline.md) for isolated comparisons.

Only aggregate counts, timestamps, and bounded display labels are kept. The last observation is cleared on session replacement, tree navigation, compaction, or model selection. There is no disk state or telemetry for this extension.

Run `node --test test/pi-context.test.mjs` for controller flow tests. With `PI_BASELINE_PACKAGE` set as in [the baseline instructions](baseline.md), `node --test test/pi-sdk.test.mjs` loads the real extension and renderer in a disposable profile, uses built-in MCP registration and a synthetic SSE response, and verifies a later hook rewrite, local UI output, and unchanged history across command invocations. It exercises a real structured announcement and identical-looking prose supplied through the system prompt of a direct server.
